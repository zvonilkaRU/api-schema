# Bug report: oapicodegen v1.3.3 — list-converter codegen эмитит `[]RoomRequestToResponse(req.Items)`, трактует функцию-конвертер как тип → `RoomRequestToResponse (function) is not a type`

**Репозиторий генератора:** github.com/ilovepitsa/oapicodegen
**Версия:** v1.3.3
**Проект-потребитель:** github.com/zvonilkaRU/api-schema
**Дата:** 2026-08-01
**Результат:** обновление v1.2.1 → v1.3.3 заблокировано, откат к v1.2.1.

## TL;DR

v1.3.3 починила регрессию v1.3.2 (Timestamp × `USE_UTC_FOR_DATE_TIME` — `undefined: time.Timestamp`
больше НЕ воспроизводится, `format: date-time` рендерится как `model.UTCTime`). НО появилась новая
регрессия: для model-list схемы с per-item Request→Response конвертером (`rooms/RoomList`) v1.3.3
эмитит `resp.Items = []RoomRequestToResponse(req.Items)` — type-conversion выражение, где
`RoomRequestToResponse` (функция) трактуется как имя типа → `RoomRequestToResponse (function) is not a type`,
`go build` падает. v1.2.1 эмитил прямой копи `resp.Items = req.Items` (компилировалось).

## Симптом

```
generated/rooms/model/models/room_list_converters.gen.go:7:17: RoomRequestToResponse (function) is not a type
```

`go build ./...` падает. Единственный затронутый файл — `room_list_converters.gen.go`.

## Что v1.3.3 починила

Регрессия v1.3.2 (`undefined: time.Timestamp` при `USE_UTC_FOR_DATE_TIME=true` — path-only cross-file
`$ref` на date-time схему резолвился в пустой стаб `time.Timestamp` вместо `model.UTCTime`) **больше
не воспроизводится**. Timestamp-поля (`Room.created_at` и др.) рендерятся корректно как `model.UTCTime`.
См. `docs/2026-08-01-oapicodegen-v1.3.2-timestamp-utctime-stub.md`.

## Новый дефект (блокер)

Для model-list схемы `rooms/RoomList` (единственная model-list схема с per-item Request→Response
конвертером) v1.3.3 эмитит:

```go
resp.Items = []RoomRequestToResponse(req.Items)
```

вместо per-item цикла. `RoomRequestToResponse` — это **функция** (`func RoomRequestToResponse(req RoomRequest) RoomResponse`),
определённая в `generated/rooms/model/models/room_converters.gen.go`. Компилятор Go отвергает
использование имени функции в type-conversion выражении `[]<ConvFunc>(slice)` →
`RoomRequestToResponse (function) is not a type`.

v1.2.1 эмитил прямой копи `resp.Items = req.Items` (компилировалось, т.к. `RoomListRequest.Items`
и `RoomListResponse.Items` — одинаковый тип `[]Room`).

Корректный вывод v1.3.3 должен быть per-item циклом:
```go
resp.Items = make([]RoomResponse, len(req.Items))
for i, v := range req.Items {
    resp.Items[i] = RoomRequestToResponse(v)
}
```

### Scope

Затронута только `rooms/RoomList` — единственная model-list схема с per-item конвертером.
`common/ListResponse` — generic `[]any`, unaffected (без per-item конвертера).

## Сгенерированный код (НЕ компилируется, v1.3.3)

`generated/rooms/model/models/room_list_converters.gen.go`:
```go
// Code generated by oapigen (dev), DO NOT EDIT.

package model

func RoomListRequestToResponse(req RoomListRequest) RoomListResponse {
	var resp RoomListResponse
	resp.Items = []RoomRequestToResponse(req.Items)
	return resp
}
```

`RoomRequestToResponse` — функция в `generated/rooms/model/models/room_converters.gen.go`:
```go
func RoomRequestToResponse(req RoomRequest) RoomResponse { ... }
```

### Для сравнения: v1.2.1 (компилируется)

`generated/rooms/model/models/room_list_converters.gen.go`:
```go
// Code generated by oapigen (dev), DO NOT EDIT.

package model

func RoomListRequestToResponse(req RoomListRequest) RoomListResponse {
	var resp RoomListResponse
	resp.Items = req.Items
	return resp
}
```

Прямой копи `[]Room` → `[]Room` (типы совпадают — `RoomListRequest.Items` и `RoomListResponse.Items`
оба `[]Room`).

## Корневая причина (гипотеза)

В v1.3.3 рендерер list-converter'а, когда item-тип имеет Request→Response конвертер, пытается
конвертировать весь slice одним выражением type-conversion `[]<ConvFunc>(slice)` вместо того, чтобы
эмитить цикл, вызывающий `<ConvFunc>(item)` для каждого элемента. Он путает имя функции-конвертера
(`RoomRequestToResponse`) с именем типа. В Go `[]FuncName(slice)` — это type-conversion выражение,
а `FuncName` — не тип → compile error.

## Ожидаемое поведение

Для list-поля с per-item конвертером эмитить per-item цикл:
```go
resp.Items = make([]RoomResponse, len(req.Items))
for i, v := range req.Items {
    resp.Items[i] = RoomRequestToResponse(v)
}
```

Либо, если конвертация не нужна (типы совпадают) — fallback на прямой копи `resp.Items = req.Items`
(как в v1.2.1).

## Workaround

Остаться на v1.2.1.
